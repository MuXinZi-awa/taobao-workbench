# 🕒 任务计划（scheduler）

定时驱动工作台功能：**到点自动执行，不经过助手**。适合早晚全量采集、按小时推一批、定时补图这类"没人盯着也得跑"的活。

## 能做什么

| 触发方式 | 说明 |
|---|---|
| **间隔** | 每 N 分钟 / 小时跑一次 |
| **一次性** | 指定日期时间跑一次，跑完自动停用 |
| **每天** | 可填多个时间点（`09:00, 21:00`）|
| **每周** | 选星期（可多选）+ 时间 |
| **每月** | 选几号（可多个）或"月末最后一天" + 时间 |
| **Cron** | 高级表达式（上面五种都能表达）|

**批处理可传参**：数据文件、每批数量、关联账号 —— 不同店铺/门类各建各的任务，互不干扰。
**断点续跑**：跑完写进度，下次自动接上（沿用 `tg_done` 机制）。

## 怎么用

1. 点「**+ 新建任务**」→ 填名称、选触发方式、选**调用功能**
2. 点「**启动守护**」→ 守护进程常驻，到点自动执行
3. 「执行记录」里看每次跑的结果和备注

**守护（daemon.py）是独立进程**：
- 动作是**跑脚本**（采集/推广）→ **不需要工作台开着**
- 动作是**调插件 API** → 需要工作台在跑
- 开机拉起：可加一个系统"点火"任务（或手动点启动）

## 动作注册表

在 `server.py` 的 `ACTIONS` 里扩展，加一项就多一个可选功能：

```python
"report_full": {
    "label": "报表 · 全量采集",
    "kind": "script",
    "script": r"...\_report_fetch.py",
    "args": [],
    "params": [{"key":"account","label":"关联账号","type":"account","default":""}],
}
```

- `args` 里用 `{key}` 占位，执行时用任务参数填充；缺参数会拒绝执行并写日志
- `params` 决定面板上显示哪些参数输入框（`type` 可为 `account` / `file` / `number`）

## 文件

| 文件 | 作用 |
|---|---|
| `manifest.json` | 插件声明 |
| `panel.html` | 前端（跟随工作台主题变量）|
| `server.py` | 任务 CRUD + 动作注册表 + 守护启停 |
| `daemon.py` | **调度守护**（零依赖，每分钟对齐 tick）|

**数据**：`workbench/data/schedule.db`（任务）、`scheduler.log`（日志）、`scheduler_heartbeat.json`（心跳）

## 注意

- 守护**单例**：重复启动会自己退出（心跳判断）
- 同一分钟不会重复触发（`last_run` 比对）
- 一次性任务跑完**自动停用**，不删
- 日志按天不清，需要的话在「设置·通用」的日志保留里统一管
