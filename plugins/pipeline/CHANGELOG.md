## 0.5.1 — 2026-11-13
- **报价与件重尺逐行填写**（ill_price_and_weight）。上一版卡在「报价表 tbody 0 行」，
  根因不是没生成，是**抓错了表**：Fusion 的 
ext-table 把表头和数据拆成两个 <table>——
  .next-table-header-inner table 只有 thead，.next-table-body table 才是数据行。
  直接遍历 document.querySelectorAll('table') 找含「批发价」的表，拿到的是表头那半。
  梓帆一句「我这边看着是有的」直接点破。
- **必须逐行，不用「批量设置」**：多个 SKU 价格不同（1.7 / 1.5），批量会把它们设成同一个值。
  脚本末尾加了校验：批发价读回必须与 spec 逐行一致，不一致就抛 Stop 并提示「检查是否误用了批量设置」。
- 实测：报价 1.7/1000 与 1.5/1000 逐行写入且不串；件重尺两行 5/5/2/2，
  体积自动算 50；「重量均不能为空」诊断消失。
- **选类目加多候选重试**：页面有残留状态时，第一个同名项往往不是目标类目。
  现在点完读路径，不匹配就换下一个候选（最多 6 个），全不中才报错。
- 已知问题：select.htm 处于残留状态时类目搜索可能不生效（输入后下拉不出），
  多候选重试也救不回来。待处理。

## 0.5.0 — 2026-11-13
- **1688 上品脚本落地（前三段）**：`publish_1688.py` 已把「选类目 → 填基础信息 → SKU Excel 导入」
  跑通并参数化，端到端实测通过。参数走 `--spec 参数.json`，不写死料号。
- **选类目**：`select.htm` 搜关键词 → 点同名叶子 → **校验已选路径**（不符就停手）→
  点「确认类目继续完善」。坑：浏览器里长期挂着旧编辑页（URL 也含 publish.htm 但带 `id=`），
  不先记页面快照就会抓到旧页、把 A 商品的内容填到 B 商品上。
- **基础信息**：按 label 文本找同容器内 input，不靠全局索引（React 重渲染会错位）。
  读回时**重新按 label 定位**：品牌/系列/货号是自定义下拉，一写就触发重渲染，
  拿旧 DOM id 读会得到 None，看起来像没写进去（实际已写入）。
- **SKU Excel 导入**（这一步是上品能不能自动化的分水岭），三个坑：
  1. 真正的上传按钮在弹窗里（「上传excel表格」），不是页面上那个全局 `input[type=file]`；
     直接 `set_input_files` 会很安静地什么也不发生。
  2. 只显示「上传成功」不够，必须点弹窗底部「确认」，规格表才会变。
  3. 「确认」按钮有两层弹窗叠加（共 2 个），要点最靠上的；
     Playwright `locator.click()` 会被遮挡超时，必须用 JS 按 y 取最上层。
- **`gen_1688_sku_excel.py`**：按类目模板生成 SKU Excel，带必填自检——
  `规格型号/电阻值/额定电压/外形/封装·外壳/容差` 任缺一个就直接退出码 3，不允许生成一个
  “导进去还得在页面上补”的文件。梓帆原话：「在 excel 里填齐了就不会有这种问题了」——实测成立。
- 实测结果：3314 双 SKU 导入后规格表 2 行 13 字段全进，包括「外形 = 方形」与
  「封装/外壳 = 2-SMD，无引线 / 2-SMD，J形引线」（**中文全角逗号**）。
  页面上原本那 5 条「不能为空」诊断全部消失，只剩发货时间/件重尺/图文详情。
- **尚未实现**：销售信息（报价方式切换后报价表 tbody 为 0 行，疑需再等或触发刷新）、
  发货时间、件重尺、主图/SKU图/详情/视频、提交。脚本跑到第三段就停，不提交。
